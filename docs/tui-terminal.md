# TUI interactive terminal contract

This is the implementation contract for Task 29. It selects a child terminal screen/parser and defines transport, ownership and verification requirements. It does not qualify a provider, platform or release. Live Codex and Claude qualification belongs to Tasks 39, 40 and 44; native Windows PTY qualification belongs to Task 43.

## Choice and verified versions

Keep Bubble Tea 2 as the application host. Use the Console-owned headless `Screen` and `Parser` APIs in `internal/terminalengine`, derived from the pinned Portalis source below with disclosed resize and bounded render-formatting patches, with Console-owned serialization, transport and supported input encoding. Use neither its Emulator controller nor its PTY, clipboard or Bubble Tea 1 application lifecycle. The existing daemon remains the only process/PTY owner. Render the library's cell screen in a bounded region; never render a raw output tail or let child escape sequences control the application's outer terminal.

## Disclosed internal engine patches

The published v0.1.0 parser saves DEC1049 cursor coordinates independently of the screen. After entering alternate mode, a 4x4 to 4x2 to 4x4 resize restores main cells but incorrectly restores cursor (3,3) instead of (1,3); the next X lands on a blank row. Actual Console View and independent public-API tests reproduce it. Their original failing WIP544bba7 and raw normal/race logs remain preserved. A naive 1049-to1047 alias passes that resize but changes valid mixed-mode behavior (1049 enter, 1047 exit, main text, 1049 restore), so it is rejected.

`internal/terminalengine` copies only ansi.go, screen.go and terminal_size.go from the immutable origin; screen.go includes the disclosed patches, original parser/screen tests, and two selection limits extracted from clipboard.go. Its complete upstream MIT license/copyright, origin and original file hashes are retained in LICENSE and UPSTREAM.json. Mechanical package renaming, the resize patch and bounded render-formatting cache are disclosed in UPSTREAM.md. This is a maintained internal derivative, not an unmodified published dependency or a second Console screen/cursor engine. No private reflection/unsafe access is permitted in Console product code, no local module replacement is used, and the library controller, PTY and clipboard I/O remain excluded. Preserve original parser/screen assertions and all prior counterproof artifacts when updating it. The published module is retained as an unchanged-semantics test oracle; legacy Bubble Tea/controller dependencies required by that oracle are not runtime hosts. The internal engine still imports legacy Lip Gloss v1 only for the Color type; that package and its initialization remain part of the runtime dependency audit, without replacing Console styling or its Bubble Tea 2 host.

The renderer caches at most 64 exact foreground/background/style formatting results per cell row, discarding the cache when the row returns. This changes formatting cost while preserving output bytes and all parser, cell, cursor, selection and synchronized-output semantics. The unchanged published module remains the rendering oracle; maximum styled and grapheme scenes retain their existing memory and qualification limits.

Every resize of an attached screen/parser must call public `Parser.ResizeChecked(rows,cols)`. The screen returns the actual main-grid crop offset from its existing resize operation; the parser uses that offset and the same dimension clamp to update its own saved DEC1049 cursor. Direct Screen.ResizeChecked does not update parser-owned state and is forbidden in the attachment actor. The attachment delivery must preserve the actual Model.View resize regression and verify that every actor resize uses Parser.ResizeChecked. Screen also rebases its DECSC/1048 saved cursor by the crop of the buffer where it was saved, preserving rendition/origin/wrap state. A saved alternate cursor after that alternate grid was discarded receives only the dimension clamp, including after alternate re-entry; the discard marker persists until a new save or reset. No lost text is reconstructed. Both RIS and DECSTR reset this saved-buffer marker. Invalid dimensions return before changing either object; no-op geometry leaves parser buffers and state intact. The correction does not rewrite child sequences or change non-resize mode/charset semantics. Primitive tests prove the original red then unchanged green, 24 crop/style/origin/wrap/charset oracle cases, DECSC/1048 saves on main and alternate grids, mixed modes including1048 split across a growth resize, mixed-mode crop literals at all byte splits, Unicode and partial UTF-8/CSI/OSC across resize, original parser/screen suites, race and compile-only Windows. These prove this narrow patch only; they do not qualify the full TUI, native Windows PTY, a provider or a release.

Before Task29 is accepted, binary archives must include THIRD_PARTY_NOTICES with the complete copied MIT notice. The narrow packaging changes may only add that notice to the archive and its exact-content verification. All geometry/resource/classifier/ownership/wire/lifecycle/signal and actual Model.View requirements below remain unchanged; one-row screens stay unsupported.

## Screen, rendering and bounded state

Maintain one owned headless screen/parser for the explicitly attached session and attachment generation. `NewScreen(rows,cols)` and `NewParser(screen)` do not spawn a process; `Feed([]byte)` retains partial UTF-8 and escape state. Screen and Parser are not concurrency-safe. Use the public `Render()` surface for displayed live/history/synchronized frames. It derives text and ANSI styles from library cell state, rather than forwarding the raw child stream. Active `CellsSnapshot()` is for inspection/tests; it must not display a partial synchronized frame. `Cell` contains Rune, Combining, FG, BG, Style and Continuation; cursor Row/Col and visibility are public. Confine Render output to the allocated region by clipping generated lines/columns with grapheme-aware ANSI utilities and ending generated styles at each region boundary. Console owns a static visible blink phase: call the public SetCursorBlinkVisible(true) after NewScreen, observed RIS and Parser.ResizeChecked, while preserving the child's separate cursorVisible setting (?25l still hides it). NewScreen/RIS otherwise leave the blink phase false, so the headless Render would omit the cursor. Prove initial/reset/resize/hidden cursor through the actual Console view. Render contains cell text/styles and the library's inline reverse-video cell cursor when those flags permit it; do not forward raw child control sequences or overlay an outer cursor from live CursorState during a synchronized frame. History rendering must also come from cell state and remain confined to that region. Virtual screen dimensions follow authoritative child geometry; a read-only viewer clips to its local viewport without resizing the child. A fresh/reconnected byte-history view remains provisional until a redraw at the known geometry. `Render()` is the public surface that honours DEC2026 synchronized output. Console must retain its own last committed Render string and geometry: engine Parser.ResizeChecked invalidates its cached string during a hold. Commit Render immediately before feeding an observed DEC2026-set boundary, so text before that boundary in the same socket frame is included. While held, use the Console-owned committed string even if the library returns an empty render after resize; never use the active-grid fallback. Show a visible synchronized-output-held indicator from DEC2026 set until reset, including empty replay, a child that never resets, and disconnect. Keep the committed frame at its previous geometry, label it as held when authoritative geometry changes, and show history browsing as unavailable while held. Never force the parser out of synchronization. Limit cumulative received bytes during a hold to 1 MiB; exceeding it freezes the last committed screen, reports a synchronized-output limit and detaches without stopping the child. No timer is needed to display the held state. Verify empty/start/resize/end, never-ending and byte-bound cases through the actual Console view; do not bypass the committed frame with an active-grid snapshot.

Eligibility fixtures passed every byte split of `éX`, `世X`, `👩‍💻X` and `🇧🇷X`, under both child DEC2027 set/reset streams, with literal row contents and independently measured rendered columns/cursor. If the local region cannot provide two rows, reject an owned resize locally with a visible too-small state; do not send a one-row resize or silently enlarge the child. Do not silently shrink the virtual screen or resize the child while read-only. Keep a positive main-history limit of 400 lines: with the 500-column maximum this bounds history to 200,000 cells and stays below 1,000 lines. `SetScrollbackLimit` limits lines; its nonpositive values disable that limit and must never be used. The library's independent main-history cell cap is 1,048,576 and its active-grid cap is 262,144; neither is Console's smaller budget. ## Input, callbacks and protocol limits

Terminal focus is explicit. Console encodes supported legacy text, Unicode, Enter, Tab, Escape, navigation and modifiers according to observed application-cursor/paste/focus modes. Portalis has no qualified public headless key encoder; do not invoke its PTY-backed controller to encode input. Send focus reports only when the child enabled them and this attachment has verified current input ownership; read-only and obsolete attachments send none. Verify the supported encodings and focus ownership against exact child bytes. Do not advertise Kitty, CSI u, modifyOtherKeys, mouse or other capabilities without separate host/protocol proofs. Child title, working-directory and OSC content are untrusted metadata; they cannot launch programs, change application paths, write the clipboard or escape the region. Metadata callbacks remain inert.

Forward Ctrl+C/Z/\\/D as 03/1a/1c/04 with child focus; q and Escape are child input. Application shortcuts act in panel/form focus. Ctrl+] is local detach: release only this client's control, close its attachment and return panel focus without stopping the child.

`SetResponseCallback` supplies already encoded parser replies synchronously. It must never block, re-enter the parser, write directly to a socket or depend on rendering. Current owners serialize replies with keys/paste in the outgoing queue; read-only or obsolete attachments discard replies. Full queues produce a visible failure, invalidate pending sends and complete owned shutdown. No io.Pipe or library Close is required by this headless API; the former x/vt pipe/disposal contract no longer applies.

Portalis privately caps grapheme extension storage at 64 bytes, CSI buffering at 4096 bytes and OSC buffering at 64 KiB. The grapheme guard uses only public cells, without duplicating segmentation: feed at most one decoded printable rune at a time, then inspect public cells in the cursor row before and after the feed, at most two rows of at most 500 cells each. This bounded row scan includes private wrapPending alternatives, continuation bases, width-growth relocation and bottom scrolling without reading private fields. The observer owns bounded byte classification outside and inside escape/control strings and pending UTF-8; only printable screen runes receive this guard, with differential parser fixtures. Record allocations and throughput of a 1 MiB printable stream at maximum width: complete it within 10 seconds in a normal non-race fixture, keeping the existing 120-second race-fixture deadline. Do not increase these limits or replace ordering with sleeps. The supported Combining storage limit is 60 bytes. If an append produces more than 60 bytes, report an unsupported grapheme and detach before feeding another rune. Starting at at most 60 bytes, one UTF-8 rune can add at most four bytes, so this check precedes the dependency's greater-than-64 drop; no complete rune is withheld waiting for a later frame. Prove the guard across cursor moves, wrap/scroll, SGR, frames and reset, including an ASCII rune after a full cluster. Console counts the complete raw sequence, including 7-bit/C1 introducers and terminators, with limits4096bytes for CSI and65536bytes for OSC. A valid final/terminator may finish exactly at that limit; reaching it without termination fails before feeding that byte. A multi-byte ST must fit within the same limit, including its ESC byte. This conservative total-byte bound stays below the dependency's buffered-payload drop thresholds; prove exact-bound success, first-over-bound failure and split ST for both introducer forms. Portalis discards DCS/APC/PM/SOS payloads without buffering in stateString/stateStringEscape; Console also counts these unsupported strings and detaches visibly after 64 KiB without a terminator. Prove 7-bit and C1 forms, split terminators, pending UTF-8 and an unterminated string. Before feeding a count-amplifying CSI operation, bound REP to 10,000 repetitions of a verified preceding plain printable ASCII cell with empty Combining. At the rightmost cursor column reject REP visibly, since private wrapPending makes the preceding-cell choice ambiguous; include a last-column fixture. Away from that column resolve the public preceding cell, stepping back over a Continuation before verifying it; other REP graphemes are visibly unsupported, so internal repeated Put calls cannot bypass the grapheme guard. Bound forward/backward tab counts to 500. Check numeric overflow and count before feeding the final byte. Other count operations must be source-audited for dimension clamping or guarded. Process at most256decoded printable runes or one complete control operation per cancellable actor turn, checking cancellation between turns. The public-cell scan may be skipped or printable ASCII may be batched only after differential proof that the path cannot create/extend Combining, including charset, insertion and wrap cases; preserve Unicode/final-glyph assertions. repeated small sequences cannot monopolize cancellation. Prove huge REP/tab counts, Unicode REP rejection, valid ASCII REP and repeated bounded controls with prompt cancel/join. Each stream limit preserves a frozen screen, displays a concrete error and performs owned detach: release only this client's verified control, close/join its attachment and preserve the child. If release is uncertain or failed, show that ownership fact and never issue another take/release automatically. Validate this across frames, including a prompt's final glyph, long combining runs, unterminated control strings and reset/reconnect. Do not add timing-dependent buffering or withhold a prompt's final glyph until another frame arrives.

Bound pending input/output to 1 MiB each and logical WebSocket messages to 64 KiB. Explicitly set 64 KiB read limits on both connections; coder/websocket 1.8.15 defaults to 32 KiB. Split larger encoded input/replay while preserving byte order. Reject oversized paste visibly before sending any of it. A failed/uncertain write is not proof the CLI consumed input; input has no delivery acknowledgment. Never replay keys, paste or replies after cancellation, transfer, reconnect or generation change.

## Owned lifecycle, exact selection and control

Console owns a serialized screen/parser actor and separately cancellable transport commands. Bubble Tea Update/View never wait on sockets or synchronous callbacks. Async results carry exact session/client/generation tags. Cancellation closes the owned socket, invalidates pending commands and joins readers/writers/producers before clearing callbacks and disposing parser/screen references. Preserve a frozen last screen with disconnected/stopped/error state. Late output, resize, control or outgoing commands cannot affect a newly selected attachment. Race fixtures cover idle/reply/write/resize cancellation and repeated detach.

Select an actual session ID from authoritative session/member/account/workspace facts. Never choose the first nearby session or replace a session/member ID with a row index. Attach cannot create a session. Use the actual TUI client ID for attachment and typed control requests. Viewing does not take control. Explicit acquisition uses `surface=tui`, under the backend's current transfer rules; another client's consent is not required by that API. `surface=none` releases only the current owner client and clears it. A 403 must not trigger another release or acquisition.

Input/resize are backend owner-client guarded. Refresh authoritative ownership through events or bounded polling with cancellation/generation guards; distinguish owned, another owner, unowned and uncertain. A lost/failed mutating control response cannot authorize local input. The socket silently ignores permission-denied input/resize errors and cannot prove current ownership. Never automatically reacquire after reconnect. Stop is an explicit action on the exact selected session ID and terminates that process only; Ctrl+C, release, detach, navigation and quit are distinct. Already exited/missing sessions are recoverable.
